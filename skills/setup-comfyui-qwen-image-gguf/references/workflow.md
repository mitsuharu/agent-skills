# ワークフローと既定表示の調整

GGUF用ワークフローを作るとき、およびComfyUIを開いたときに別のワークフローが表示される問題に対処するときに読む。

## GGUF用ワークフローを作る

1. ComfyUI公式のQwen-Image 2.1 Text-to-Imageテンプレート（ComfyUI画面のテンプレート一覧にある）を取得する。
2. 拡散モデルの読み込みノード（`Load Diffusion Model` / `UNETLoader`）を、ComfyUI-GGUFの `Unet Loader (GGUF)`（`UnetLoaderGGUF`）に置き換え、配置したGGUFファイルを選ぶ。
3. テキストエンコーダ（`Load CLIP`）とVAE（`Load VAE`）は配置したファイル名に合わせる。
4. **プロンプト拡張のノード群を外す。** 公式テンプレートはプロンプト拡張用に別のモデルを参照しており、ダウンロードしていないとモデル不足のエラーで実行できない。拡張ノードを削除し、ポジティブプロンプトを直接テキストエンコードへつなぐ。ユーザーがプロンプト拡張を望む場合だけ、対象モデルを追加でダウンロードする。
5. サンプラー設定はテンプレートの値を基本とし、1024×1024・25ステップで動作確認する。
6. `ComfyUI\user\default\workflows\Qwen-Image-2.1-UC_GGUF_t2i.json` に保存し、左のワークフロー一覧に表示されることを確認する。

## 起動時に別のワークフロー（Z-Imageのサンプル）が開く問題

### 症状

初めてComfyUIを開くと、`z_image_turbo_bf16.safetensors` などのモデルが見つからないという警告が出る。

### 原因

ブラウザに前回のワークフローが保存されていない初回起動時、ComfyUIのフロントエンドは付属のサンプル（Z-Image用）を既定のグラフとして表示する。Qwenのモデルや設定の問題ではない。

### 対処

`custom_nodes\qwen21-default-workflow` に、ノードを持たないフロントエンド拡張（`__init__.py` で `WEB_DIRECTORY` を公開し、`web\` 以下にJavaScriptを置く）を作る。
拡張は起動時に表示中のグラフが付属サンプルかどうかを判定し、そうであれば `Qwen-Image-2.1-UC_GGUF_t2i` のワークフローを読み込む。
ユーザーが自分で編集したワークフローは置き換えない。

作成後、次を確認する。

- ComfyUIを再起動する（起動中のComfyUIには反映されない）。
- シークレットウィンドウなど保存データのない状態で開き、警告が出ずにQwenのワークフローが開く。
- 付属サンプルの「Unsaved Workflow」タブが残る場合があるが、閉じてよいとユーザーに伝える。
