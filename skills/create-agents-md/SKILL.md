# AGENTS.mdを作成する

[ベースのAGENTS.md](assets/AGENTS.md) を土台に、対象リポジトリに合わせたAGENTS.mdを作る。
ベースには、どのリポジトリでも共通の開発ルールと、リポジトリごとに埋める `{{...}}` のプレースホルダが入っている。

## 対象リポジトリを調べる

- 対象リポジトリの `AGENTS.md`、`CLAUDE.md`、README、`docs/`、ビルド設定（`Package.swift`、`package.json` など）、`.github/` を確認する。
- 現在のブランチと未コミットの変更を確認し、作業用ブランチ（`docs/agents-md` など）を作る。`main` には直接コミットしない。
- 次の値をファイルから読み取る。読み取れず、作業に影響するものだけユーザーに確認する。
  - プロジェクトの概要と主目的
  - 言語・ランタイムのバージョン、依存の方針、対応プラットフォーム
  - ビルド・テスト・フォーマットのコマンド、テストフレームワーク
  - 作者のGitHubのユーザー名
  - GitHub Actionsを使っているか、リリースやタグの運用があるか

## AGENTS.mdを書く

1. ベースを `AGENTS.md` としてコピーし、`{{...}}` をすべて埋めるか、指示どおり行・節ごと削除する。推測で埋めず、ファイルで確かめた値かユーザーの回答だけを書く。
2. 共通ルールの文言は原則変えない。リポジトリの事情で合わない項目（GitHub Actionsを使わない場合の節など）だけを削除・調整し、調整した理由を報告に含める。
3. ドメイン固有のルール（アーキテクチャ、リリース手順、動作確認の方法など）は、該当する節に追記するか、独立した節を足す。長くなる詳細は `docs/` に置いてリンクする。
4. 既存のAGENTS.mdがある場合は上書きしない。既存の内容を残し、ベースにあって既存にない共通ルールを足す形で揃える。既存のルールとベースが矛盾する場合は、どちらを採るかユーザーに確認する。
5. `CLAUDE.md` は `@AGENTS.md` の1行にして、AGENTS.mdを唯一の正とする。既存のCLAUDE.mdに独自の内容があれば、AGENTS.mdへ移してから置き換える。

## 検証して仕上げる

- `grep -n '{{[^ ]' AGENTS.md` で埋め忘れのプレースホルダがないことを確かめる（GitHub Actionsの式 `${{ ... }}` は対象外）。
- 書いたコマンドが実在し、READMEやビルド設定と一致することを確かめる。実行できる環境なら実際に実行する。
- 文書の言語が日本語で統一され、識別子・パス・コマンドだけが英語になっていることを確かめる。
- `git diff --check` を実行し、AGENTS.mdとCLAUDE.mdの追加・変更をコミットしてPRを作る。コミットとPRはAGENTS.mdに書いたルール（Conventional Commits、`Co-authored-by`、PR説明の4項目）に従う。
- 報告には、埋めた値の出典、削除・調整した共通ルール、ユーザーに確認が必要な点を含める。
