# Skillを追加する

## 作業対象と目的を確かめる

- 編集対象はユーザーが指定した `agent-skills` のチェックアウトとする。インストール済みのこのSkillのフォルダを編集対象と取り違えない。
- 対象の `AGENTS.md`、README、Gitの状態を確認し、共通のブランチ・コミット・PRルールに従う。対象リポジトリが特定できない場合は、ファイル作成前に場所を確認する。
- 依頼から用途、利用場面、入力、期待する成果物を整理する。作業に影響する不明点だけ質問し、依頼にない機能を増やさない。
- `skills/` の既存Skillの名前と説明を確認し、近いものだけ本文も読む。同じ目的のSkillがある場合は重複を増やさず、既存Skillの拡張で満たせるか判断する。依頼の範囲が変わる場合はユーザーに確認する。

## Skillを作成する

1. 用途が分かる短い名前を選ぶ。このリポジトリでは英小文字・数字・ハイフンを使い、1〜64文字、先頭末尾のハイフンと連続ハイフンは禁止する。既存名と重複させない。
2. `skills/<skill-name>/SKILL.md` を作成する。YAML frontmatterにディレクトリ名と同じ `name` と、何を行い・どの依頼で使うかが分かる `description` を書く。説明は1〜1024文字の文字列とし、短く具体的にする。
3. 本文には必要な判断基準、手順、成果物、検証方法を書く。汎用的な助言や共通Gitルールを繰り返さない。特定のローカルパスや利用できない別Skillへの依存を持ち込まない。
4. 詳細な資料は必要に応じて `references/` に分け、本文から相対リンクで「いつ読むか」を案内する。すべての資料を最初に読み込ませない。反復処理が必要なら `scripts/`、成果物用の素材が必要なら `assets/` を追加する。空ディレクトリや雛形の残骸は作らない。
5. READMEのSkill一覧にリンクと用途を追加する。利用条件や追加手順が変わる場合だけ関連ドキュメントも更新する。

## 検証して仕上げる

完成後に [検証チェックリスト](references/validation.md) を読み、構造・frontmatter・参照・代表的な利用場面を確認する。スクリプトを追加した場合は実行して確認する。

対象リポジトリのルートで `npx skills add . --list` を実行し、新しいSkillが表示されることを確認する。このコマンドは検出確認であり、完全な仕様検証ではない。

変更を目的ごとにコミットしてPRにまとめる。完了報告にはSkill名、配置先、呼び出し例、検証結果を含め、実行できなかった検証があれば明記する。
